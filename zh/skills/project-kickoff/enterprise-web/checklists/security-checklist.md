# 安全设计检查清单

> **用途**: 系统设计阶段的安全方案逐项确认  
> **使用时机**: Phase 3 系统设计、代码实现前审查、上线前复查  
> **关联**: `enterprise-concerns.md` 中的安全相关项是高层关注点，本清单是具体实施检查

---

## 1. 认证与会话管理

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 认证方案选型已确定 | P0 | JWT / Session / OAuth，记录选型理由 | ⬜ |
| Access Token 有效期合理 | P0 | 建议 15-30 分钟 | ⬜ |
| Refresh Token 安全存储 | P0 | httpOnly Cookie，非 localStorage | ⬜ |
| Refresh Token 有效期合理 | P1 | 建议 7-30 天 | ⬜ |
| Token 黑名单/撤销机制 | P1 | 登出、密码变更时使旧 Token 失效 | ⬜ |
| 登录失败锁定 | P1 | 连续 N 次失败后锁定 M 分钟 | ⬜ |
| 并发登录策略已定义 | P2 | 单设备 / 多设备 / 不限制 | ⬜ |

---

## 2. 密码存储

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 密码使用安全算法哈希 | P0 | bcrypt 或 Argon2id，**禁止** MD5/SHA1 | ⬜ |
| 自动加盐 | P0 | bcrypt 自带盐值；Argon2 需配置 | ⬜ |
| 密码强度校验 | P1 | 最少 8 位，含字母和数字 | ⬜ |
| 密码不以明文出现在日志中 | P0 | 日志脱敏 | ⬜ |
| 密码不以明文出现在 API 响应中 | P0 | 响应序列化时排除 | ⬜ |

---

## 3. 敏感数据加密

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 敏感数据已识别并标记 | P0 | 列出哪些字段是敏感数据 | ⬜ |
| 敏感字段使用对称加密存储 | P0 | AES-256-GCM | ⬜ |
| 加密密钥不在代码库中 | P0 | 环境变量或密钥管理服务 | ⬜ |
| 加密密钥轮换方案 | P2 | 计划密钥过期和更新流程 | ⬜ |
| 数据库备份也加密 | P1 | 备份文件不裸存 | ⬜ |

---

## 4. 传输安全

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| HTTPS (TLS 1.2+) | P0 | 所有生产环境通信加密 | ⬜ |
| HTTP → HTTPS 重定向 | P1 | 不允许明文访问 | ⬜ |
| 安全响应头已配置 | P1 | HSTS, X-Content-Type-Options, X-Frame-Options | ⬜ |
| API 不在 URL 中传递敏感参数 | P1 | Token、密码等走请求体或头 | ⬜ |

---

## 5. 输入校验与防注入

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 所有用户输入都经过校验 | P0 | 长度、格式、范围 | ⬜ |
| SQL 注入防护 | P0 | 使用 ORM 参数化查询，禁止拼接 SQL | ⬜ |
| XSS 防护 | P1 | 前端输出转义，CSP 头 | ⬜ |
| CSRF 防护 | P1 | Token-based（JWT 方案自带）或 SameSite Cookie | ⬜ |
| 文件上传校验 | P1 | 类型、大小、内容检查 | ⬜ |
| 路径遍历防护 | P1 | 文件操作不拼接用户输入 | ⬜ |

---

## 6. 权限控制

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 每个 API 端点都有权限检查 | P0 | 无遗漏 | ⬜ |
| 垂直越权防护 | P0 | 普通用户不能访问管理接口 | ⬜ |
| 水平越权防护 | P0 | 用户只能访问自己的数据 | ⬜ |
| 权限检查在服务端执行 | P0 | 前端权限仅用于 UI 显示 | ⬜ |
| 默认拒绝原则 | P1 | 未明确授权的操作一律拒绝 | ⬜ |

---

## 7. CORS 策略

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| CORS 白名单已配置 | P1 | 只允许已知的前端域名 | ⬜ |
| 生产环境禁止 `*` 通配符 | P1 | 开发环境可以宽松 | ⬜ |
| 允许的 HTTP 方法已限制 | P2 | 只开放需要的方法 | ⬜ |
| Credentials 模式已正确配置 | P1 | 与 Cookie 认证方案配合 | ⬜ |

---

## 8. 日志安全

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 日志中不含密码 | P0 | 请求日志脱敏 | ⬜ |
| 日志中不含完整 Token | P0 | 最多记录前 8 位 | ⬜ |
| 日志中不含敏感业务数据 | P1 | 身份证号、银行卡号等 | ⬜ |
| 错误响应不暴露技术栈细节 | P1 | 不返回堆栈信息给前端 | ⬜ |
| 敏感操作有审计日志 | P1 | 登录、权限变更、数据删除 | ⬜ |

---

## 9. 依赖安全

| 检查项 | 优先级 | 实施建议 | ✓ |
|--------|:------:|----------|:-:|
| 依赖版本锁定 | P1 | lock 文件提交到代码库 | ⬜ |
| 已知漏洞扫描 | P2 | pip-audit / npm audit | ⬜ |
| 定期更新依赖 | P2 | 建立更新计划 | ⬜ |

---

## 使用说明

1. **系统设计阶段**：逐项检查，记录每项的具体实施方案
2. **代码实现前**：确认 P0 项全部有方案
3. **上线前复查**：全部勾选确认
4. **定期回顾**：项目演进中检查是否有新增安全需求
